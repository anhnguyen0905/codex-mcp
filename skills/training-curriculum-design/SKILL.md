# Training & Curriculum Design (objectives → assessment → lessons, in that order)

## Method — backward design

1. **Define outcomes first.** What must learners *do* after training that they can't do now?
   Write objectives before any content exists.
2. **Design assessments second.** Decide how you'll verify each objective before writing lessons —
   a lesson that can't be assessed is decoration.
3. **Build lessons last.** Content exists only to get learners through the assessments.
   Cut anything that doesn't serve an objective ("nice to know" is the enemy of "need to do").

## Learning objectives — Bloom's levels and verb discipline

```
Remember   → list, define, recall          Analyze  → compare, categorize, diagnose
Understand → explain, summarize, classify  Evaluate → judge, critique, justify
Apply      → use, execute, demonstrate     Create   → design, build, compose
```

- Format: **"Given [condition], the learner will [observable verb] [object] to [standard]."**
  E.g. "Given a sample ticket, the learner will triage it to the correct queue within 2 minutes."
- Banned verbs: *know, understand, appreciate, be familiar with* — unobservable, untestable.
- Match the level to the job: don't teach Remember-level facts when the job requires Apply.

## Structure — curriculum → module → lesson

- **Curriculum**: sequence modules by prerequisite dependency, not topic elegance. State entry
  requirements and total time budget up front.
- **Module**: 2–5 objectives, one assessment covering all of them, 30–90 minutes of learner time.
- **Lesson plan** (per session): objective(s) → hook/relevance (2–5 min) → instruction with worked
  example → guided practice with feedback → independent practice → assessment/check → recap.
  Target ≥50% of session time on learner practice, not presenter talking.
- **Workshop agenda**: same skeleton plus timeboxes per block, materials list, and a facilitator
  contingency ("if running 15 min over, cut X, never Y").
- **E-learning storyboard**: one row per screen — screen ID, on-screen text, narration, media,
  interaction, branching. Every 3–5 screens end in an interaction; 20+ passive screens = a PDF.

## Assessment and rubrics

- **Quiz items**: one objective per item; distractors must be plausible errors (a wrong answer a
  real learner would make), not jokes; avoid "all of the above" and negatively-worded stems.
- **Rubric**: rows = criteria (from objectives), columns = 3–4 performance levels with observable
  descriptors per cell. "Good/fair/poor" without descriptors is a vibe, not a rubric.
- **Mastery threshold**: state the pass bar (e.g. 80%) and what happens on failure (remediate and
  retest, not "move on anyway").

## Measurement — skill gap in, Kirkpatrick out

```
Skill gap    = required proficiency (per role) − assessed current proficiency
Kirkpatrick  L1 Reaction  → post-session survey (satisfaction, relevance)
             L2 Learning  → pre/post assessment delta
             L3 Behavior  → on-the-job observation/metrics 30–90 days later
             L4 Results   → business KPI movement attributable to training
```

- Run the gap analysis *before* design: train only the gap, not the whole domain.
- L1 is the weakest signal — happy learners ≠ effective training. Never report L1 alone as
  effectiveness. Commit to at least L2 for every program and L3 for anything expensive.

## Failure modes

- Content-first design: assembling slides by topic, then bolting a quiz on at the end.
- Objectives written with unobservable verbs, so nothing can actually be assessed.
- 90-minute lecture blocks with zero practice — retention collapses without retrieval.
- One monster assessment at the end instead of a check per module (failure discovered too late).
- Onboarding curricula that mirror the org chart ("week 2: meet the finance team") instead of the
  first 90 days of actual job tasks.
- Reporting smile-sheet (L1) scores as proof the training worked.
- No versioning or ownership — the curriculum rots as the job changes.

## Reviewer checklist

- [ ] Every objective uses an observable verb + condition + standard
- [ ] Every objective maps to at least one assessment item; every lesson maps to an objective
- [ ] ≥50% of learner time is practice/interaction, not exposition
- [ ] Quiz distractors are plausible errors; rubric cells contain observable descriptors
- [ ] Pass bar and remediation path stated
- [ ] Skill gap analysis done before design; scope limited to the gap
- [ ] Measurement plan reaches at least Kirkpatrick L2 (L3 for high-cost programs)
- [ ] Total learner time budget stated and per-module times sum to it

## Provenance

Standard instructional design practice (backward design, Bloom, Kirkpatrick). Timing and threshold
figures are **derived, unverified** defaults — calibrate against the audience and pilot results.
